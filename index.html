01 // Distributed Ingestion & Rate-Limiting Engine

Multi-Cadence Scheduler & Sliding-Window API Budget

  • Sliding-Window Rate Limiter: Custom TornClient and TornRateLimiter enforce per-user rolling windows capped at 90 req/min below the upstream 100 req/min ceiling, with HTTP 429 exponential backoff and multi-tier key probing (Minimal, Limited, Full Access, Faction AA).
  • Single-Bill Request Consolidation: Per-minute SyncTornUserStatus merges 15+ API slices (bars, battle stats, cooldowns, perks, money, missions, equipment, property) into a single upstream request, with automatic fallback degradation if slices are refused.
  • Priority Queue Isolation: 6 domain-segmented schedules orchestrate 30-second live chain/retaliation polling (SyncFactionRetaliationWindows on isolated faction-retaliation Horizon queues), 1-to-15-minute war/crime sweeps, and self-throttling 2-second historical backfill chains (BackfillUserGrowthSnapshots, SyncTornUserLogs).

02 // Workforce Scheduling & Slot Optimization

OC 2.0 Staggered Scheduler & Event-Sourced Ledger

  • Staggered Sequential Slot Math: Models 24-hour sequential slot planning via T + (K-1) × 24h join windows, eliminating up to 15 idle member-days per 6-slot crime so high-throughput operators can chain 5 concurrent 24-hour slot commitments.
  • CPR Fitness & Participation Modeling: Projects per-member, per-slot Checkpoint Pass Rates (oc_member_slot_fitness) from live API keys and historical slot outcomes, matching operators across anchor, flex, and juggler participation profiles.
  • Non-Destructive Re-Routing & Event Ledger: Issues persisted recommendations (oc_recommendations) supporting local single-slot re-routing without disturbing locked-in operators, backed by append-only event tables (oc_member_events, oc_slot_history) and automated effort-weighted payout cycles (oc_payout_cycles).
